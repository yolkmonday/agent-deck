# Agent Deck P6: Project CRUD and project picker in the terminal

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A saved list of projects the user manages (create, edit, delete, reorder), so starting a terminal session is "pick a project" instead of typing a path.

**Architecture:** A `project` table in the dashboard's own SQLite index. Five Tauri commands. A Project page for the CRUD, plus a project picker in the new-session dialog that fills the working directory automatically. Projects can be seeded in one click from directories the dashboard already knows (live sessions and the history index).

**Tech Stack:** Same as P5.

**Spec:** Extends `docs/superpowers/specs/2026-09-22-agent-deck-design.md`. No mockup exists for this screen; follow the visual language of `docs/design/07-kelola-provider.png` (left form, right list).

## Command API (the contract)

```ts
// invoke("projects_list") -> Project[]          // ordered by `sortOrder` asc, then `name` asc
interface Project {
  id: string;            // uuid-ish, generated by the backend
  name: string;
  path: string;          // absolute, no trailing slash, `~` expanded
  defaultProfile: string | null;  // a TermProfile id: "claude" | "opencode" | "codex"
  color: string | null;  // hex like "#4C9AFF", or null
  sortOrder: number;
  lastUsedMs: number | null;
  exists: boolean;       // computed at read time: the directory exists right now
}

// invoke("project_create", { input: ProjectInput }) -> Project
// invoke("project_update", { id: string, input: ProjectInput }) -> Project
interface ProjectInput { name: string; path: string; defaultProfile: string | null; color: string | null; sortOrder: number }

// invoke("project_delete", { id: string }) -> null
// invoke("project_touch", { id: string }) -> Project        // sets lastUsedMs = now
// invoke("project_suggestions") -> ProjectSuggestion[]      // known dirs not saved yet
interface ProjectSuggestion { name: string; path: string; source: "live" | "history"; messages: number }
```

Validation on create and update, each with its own error string:
- `name` trimmed, 1-60 characters → `nama tidak boleh kosong` / `nama terlalu panjang`
- `path` must be absolute after `~` expansion → `path harus absolut`
- the path must exist and be a directory → `folder tidak ditemukan`
- `path` is unique after normalisation → `project dengan folder ini sudah ada`
- `defaultProfile`, when set, must be one of the known profile ids → `profil tidak dikenal`

### Task 3: Project commands

**Files:** Modify `src-tauri/src/lib.rs`

**Interfaces:**
- The six commands from the Command API, each returning `Result<T, String>`.
- `Project.exists` is computed per read with `std::path::Path::is_dir`, never stored.
- `project_create` generates the id and, when `sortOrder` is 0, assigns `max(sort_order) + 1` so new
  projects land at the end.
- `project_suggestions` merges two sources and excludes any path already saved:
  - **live**: the distinct `cwd` values in the current live snapshot, with `source: "live"` and `messages: 0`
  - **history**: `Store::known_project_dirs()` gives project NAMES with counts; match each name against
    the live snapshot's cwds and against `<home>/Dev/<name>` to recover a path, and skip a name whose
    path cannot be resolved to an existing directory. Set `source: "history"` and the message count.
  - Sort: live first, then history by `messages` descending. Cap at 30.

## Self-Review

- **Coverage:** create, read, update, delete, reorder and "touch" (Tasks 1-3), the management screen
  (Task 4), and the picker that makes the terminal one click (Task 5).
- **Known limitation, stated in Task 3:** the history index stores project NAMES, not absolute paths,
  so a suggestion from history can only be resolved when the name matches a live session's cwd or
  `<home>/Dev/<name>`. Names that cannot be resolved are skipped rather than guessed. Storing the
  full cwd in the index would fix this properly and is a candidate for a later phase.
- **Type consistency:** `Project`, `ProjectInput` and `ProjectSuggestion` are identical in the
  Command API section, Task 3's wire structs and Task 4's TypeScript.
